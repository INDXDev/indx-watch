# `iw --json`: the fields agents read

The contract is `packages/cli/src/json.ts` in the INDX Watch repository (`CommandData`, `ErrorEnvelope`); the command reference is `docs/spec/cli.md`. This page lists only the fields the skills use. Shapes may gain fields; never fail on an unknown field.

## Envelope

| Field             | Meaning                                                                                                                                                                                                              |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ok`              | `true` on success. `false` on errors **and** on a "no" answer (exit 1).                                                                                                                                              |
| `command`         | The command name, e.g. `"check"`, `"new"`, `"skills install"`.                                                                                                                                                       |
| `data`            | Command result (below). Also present on a "no" answer from `check` and `status --gate`.                                                                                                                              |
| `warnings[]`      | Problems: `{ severity, code, file?, path?, message }`.                                                                                                                                                               |
| `error.code`      | `CHECK_FAILED`, `GATE_FAILED`, `USAGE`, `NOT_FOUND`, `AMBIGUOUS_REF`, `NO_BUNDLE`, `UNSUPPORTED_SCHEMA`, `INVALID_CONFIG`, `INVALID_INPUT`, `SECRETS_FOUND`, `STORE_ERROR`, `EXTERNAL_TOOL`, `CONFLICT`, `INTERNAL`. |
| `error.details[]` | Usually problems, same shape as `warnings[]`.                                                                                                                                                                        |

## Statuses and verdicts

- Verdicts: `pass`, `fail`, `blocked`, `skipped`, `needs_review`. A verdict is computed by the decision policy from judgements; it is never stored on the run.
- Test case / AC / use case statuses, worst first: `uncovered` > `fail` > `needs_review` > `stale` > `blocked` > `untested` > `waived` > `pass`.
- `stale`: the test case or a fixture it used changed since the run. Re-run it.
- Plan item statuses: `todo`, `done`, `blocked`, `review`.

## Decision policy rules (what `decision.rule` means)

| Rule | Verdict                                                                              |
| ---- | ------------------------------------------------------------------------------------ |
| 1    | Last human judgement wins                                                            |
| 2    | Reported or judged `blocked` / `skipped`                                             |
| 3    | An `assert` failed → `fail`                                                          |
| 4    | An `llm` judgement failed with confidence ≥ `llm_fail_confidence` → `fail`           |
| 5    | A visual diff over the threshold → `needs_review`                                    |
| 6    | An `llm` judgement below `llm_pass_confidence`, or `fail`/`unknown` → `needs_review` |
| 7    | Priority in `require_human_for`, or mode `hybrid` → `needs_review`                   |
| 8    | Every judgement passed → `pass`                                                      |
| 9    | No judgements → `needs_review`                                                       |
| 10   | Anything else → `needs_review`                                                       |

Full definitions: `docs/spec/concepts.md#decision-policy`.
