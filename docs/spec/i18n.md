# Internationalization

INDX Watch is bilingual-ready: the UI ships in English and Japanese, and content (use cases, test cases, fixtures) can carry translations with a review status. Testers may not share a language with the authors; every run records which language the tester read.

## UI locales

- UI strings live in `packages/web/src/messages/{en,ja}.json` (flat keys, ICU-style placeholders `{count}`). Both files must have identical key sets; a unit test enforces it.
- CLI messages are English only in v0.1. JSON output is locale-independent.
- Locale selection: user choice (stored in the browser) → `Accept-Language` → project `source_locale`.
- Dates and numbers use `Intl` with the selected locale.

## Content translations {#content-translations}

The source language of a project is `project.source_locale`. Any translatable entity may carry `[i18n.<locale>]` tables for other locales in `project.locales`.

| Entity | Translatable fields |
|---|---|
| Feature | `title`, `description` |
| Use case | `title`, `actor`, `goal`; per criterion: `text` |
| Test case | `title`, `preconditions`; per step: `instruction`, `expected` |
| Fixture | `title` |
| Environment | `title`, `guide` |

Each translation table has `status` and `source_hash`:

| `status` | Meaning |
|---|---|
| `machine` | Machine translation, not reviewed |
| `reviewed` | A person reviewed it against the source |
| `stale` | *(computed)* The source changed since translation |

`source_hash` = first 12 hex of SHA-256 over the canonical source fields it translates. When the current source hash differs, tools treat the translation as `stale` regardless of the stored status; `iw check` warns and the UI shows the source text with a "translation outdated" badge. Translating writes the current hash. Example: `TC-4` in [`examples/shop`](../../examples/shop/.indx-watch/specs/FEAT-2-checkout/UC-2-guest-applies-coupon/TC-4-expired-coupon.toml).

Resolution is one function, `localize(entity, field, locale)` in `packages/core`: translation if present and not stale (or stale allowed by the caller) → source text, plus a flag saying which was used.

Translation itself (AI or human) is done by agents through skills or by editing files; INDX Watch v0.1 does not call a translation API.

## Literal strings {#literal-strings}

Text in double quotes inside a step (`press "Place order"`) or in Japanese corner brackets (`「Place order」`) is a **literal on-screen string of the app under test**. It must appear exactly as the app shows it, in any translation. Translators and AI skills keep it verbatim; `iw check` warns when a translation lacks a literal that appears in its source.

## Recorded locale

Every run records `locale`: the content language the executor read (the manual runner records the UI's content locale; agents record the locale of the text they were given).

## Acceptance criteria

- [ ] `en.json` and `ja.json` have identical keys (unit test).
- [ ] Editing a step's `expected` text makes that step's `[steps.i18n.ja]` translation `stale` in `iw check` output and in the UI.
- [ ] `localize()` falls back to the source text and reports `fallback: true` when no valid translation exists.
- [ ] `iw check` warns when a translation drops a quoted literal present in the source.
- [ ] A run recorded from the UI in Japanese has `locale = "ja"`.
