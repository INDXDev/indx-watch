SPEC-08 · 多言語

多言語設計（日本語・英語）

テスターには日本語を読まない人もいます。画面の文言だけでなく、ユースケース・完了条件・テスト手順・コメントなどの中身も日本語と英語の両方で持てるようにします。原文を 1 つに決め、もう一方は翻訳として版と状態を管理します。

状態 ドラフト v0.1更新 2026-11-19関連 データモデル · AI ネイティブ設計

なぜ必要か

  • QA を外部や海外のメンバーに頼むことがある。英語しか読めないテスターが、日本語の手順を推測で実行すると誤判定が起きる。
  • テスト対象のアプリ自体が日本語版・英語版を持つことがある。テスターが読む言語とテスト対象の画面の言語は別物として扱う必要がある。
  • 翻訳を人が毎回書くのは続かない。AI が翻訳し、重要なもの（P0 の手順など）だけ人が確認する。

対象の 3 分類

分類例持ち方誰が書く
UI 文言ボタン「合格」/ Pass、メニュー、エラーメッセージ、状態ラベルリポジトリ内のメッセージファイル apps/web/messages/{ja,en}.json開発者（コードと一緒に PR で変更）
コンテンツユースケース名、完了条件、テスト手順・期待結果、前提条件、入り方ガイド、フィクスチャの説明、計画名D1。原文は各テーブルの列、翻訳は translations利用者（原文）と AI（翻訳）、確認は利用者
自由記述・AI 出力コメント、不合格時の「実際の結果」、ジャッジの判定理由、AI 要約原文と書いた言語を保存。翻訳は表示時に作って translations にキャッシュ利用者・AI

翻訳しないもの: 表示キー（TC-128）、フィクスチャの値そのもの（クーポンコード、テスト用の名前・住所）、URL、コード、スクリプト。

基本ルール

  1. 原文は 1 つ。翻訳対象のエンティティは source_locale（ja / en）を持ち、原文は通常の列に入れる。日本語で書いた UC は原文が日本語、英語のテスターが書いたコメントは原文が英語。
  2. 翻訳は別行。もう一方の言語は translations に 1 フィールド 1 行で入れ、作り手（AI / 人）と状態（AI 翻訳 / 確認済み / 古い）を持つ。
  3. 原文が変われば翻訳は「古い」。翻訳時の原文ハッシュを保存し、一致しなくなったら古い扱いにして再翻訳する。
  4. 実行は見たものを記録。テスターが英語の AI 翻訳を見て実行したなら、そのことを実行記録に残す。
  5. 画面の文言は原語のまま引用。テスト対象の画面に出る文字列は翻訳せず、訳を括弧で添える（引用ルール）。
  6. P0 は確認済み翻訳。担当者の言語が原文と違う P0 の計画アイテムは、翻訳が「確認済み」になるまで警告を出す（アサインは可能）。

データの持ち方

列を title_ja / title_en のように増やす方法と、JSON に両言語を入れる方法も検討しました。翻訳ごとに「誰が・どのモデルで・いつ・確認したか」を記録したいので、別テーブル方式にします。言語を追加するときもスキーマを変えずに済みます。

DDL は データモデル にあります。読み出しは packages/core の localize(entity, field, locale) 1 つに集約し、各画面で個別に分岐を書かないようにします。

// 表示用に解決した結果。UI はこれだけを受け取る
type LocalizedField = {
  text: string;               // 表示する文字列
  locale: "ja" | "en";        // text の言語
  isSource: boolean;          // 原文か
  status?: "machine" | "reviewed" | "stale";  // 翻訳の場合の状態
  source?: { text: string; locale: "ja" | "en" }; // 「原文を表示」用
};

解決の順序

  1. 表示言語 = ユーザー設定 users.locale（未設定ならブラウザの Accept-Language、それもなければ ja）。
  2. 原文の言語が表示言語と同じなら原文を返す。
  3. 違えば translations から status != 'stale' の行を返す。
  4. なければ原文を返し、画面に「翻訳中」を出して翻訳ジョブを投入する（Queue）。完了すると画面が更新される。

翻訳のライフサイクル

stateDiagram-v2
  [*] --> machine: AI が翻訳（保存時・表示時）
  [*] --> reviewed: 人が直接書く
  machine --> reviewed: 人が確認・修正
  machine --> stale: 原文が変わった
  reviewed --> stale: 原文が変わった
  stale --> machine: 再翻訳
  stale --> reviewed: 人が更新
  • 変更検知: 可変フィールド（UC の名前など）は保存時に原文ハッシュを計算し、同じフィールドの翻訳のハッシュと違えば stale にする。
  • 版の引き継ぎ: TC の新しい版を作るとき、ステップごとに原文ハッシュを比べ、同じなら前の版の翻訳をそのままコピーする（再翻訳しない。確認済みも引き継ぐ）。
  • 確認: 翻訳の確認は S04 の「翻訳」タブで原文と並べて行う。確認者は reviewed_by に残る。確認できるのはその言語を設定しているユーザー、または manager 以上。
  • 用語集: プロジェクトごとの glossary_terms（例: 完了条件 = Acceptance criteria、合格 = Pass、商品名は訳さない）を翻訳プロンプトに必ず入れる。

実行時のスナップショット

実行の記録は後から変わってはいけません（バージョンとスナップショット）。翻訳も同じ扱いです。

  • runs.display_locale: 実行者が手順を読んだ言語。
  • run_steps.instruction / expected: 原文をコピー。
  • run_steps.i18n_json: 実行時に表示した翻訳をコピー。例 {"en": {"instruction": "...", "expected": "...", "status": "machine"}}。
  • 不合格の調査で「AI 翻訳を読んで誤解した」ことが分かるように、S06・S05 の結果表示に「英語の AI 翻訳で実行」と表示する。
  • ブラウザエージェントには原文と翻訳の両方を渡す。画面の言語は runs.app_locale（テスト対象アプリの表示言語。環境やデータ駆動の行で指定）で決まる。

画面文言の引用ルール

期待結果には、テスト対象の画面に表示される文字列がそのまま入ります。これを翻訳すると、英語のテスターが画面上で探せなくなります。

原文（日本語）

「このクーポンは有効期限が切れています」と表示され、割引が適用されない

英語の翻訳

The message 「このクーポンは有効期限が切れています」 (“This coupon has expired”) is shown and no discount is applied.

  • 原文で画面の文字列を書くときは「」で囲む（英語原文では "..." ではなく「」も可。エディタに「画面の文言として挿入」ボタンを置く）。
  • 翻訳プロンプトは「」内を変えずに残し、括弧で訳を添える。翻訳後に「」の中身が原文と一致するか機械的に検証し、違えば翻訳をやり直す。
  • テスト対象アプリが英語表示のとき（app_locale = en）は、TC 側で英語の期待文言を別に持つ必要がある。これは翻訳ではなくデータなので、dataset フィクスチャ（言語ごとの行）か TC のパラメータで持つ。

AI 翻訳

  • 翻訳は Queue（translate）経由で非同期に実行する。1 ジョブ = 1 エンティティの全フィールドをまとめて 1 回の呼び出し（文脈がそろうので訳が安定する）。
  • 入力: 原文フィールドの JSON、プロジェクト用語集、対象の画面 ID（どこに表示されるか）。出力: 同じキーの JSON（構造化出力）。
  • 検証: 「」内の文字列、{{FX-3.code}} のような変数、表示キー、URL が原文と一致すること。不一致は 1 回だけ再試行し、だめなら原文表示のまま「翻訳失敗」。
  • 費用: 保存時翻訳はプロジェクトの AI 予算（ai_budget_usd）に含める。表示時翻訳はキャッシュするので 1 フィールド 1 回。
  • モデルとプロンプト版を translations.model / prompt_version に保存する。

外部への出力

出力言語
メール・Slack 通知受け取る人の users.locale。チャンネル宛てはプロジェクト設定 settings_json.locale（既定 ja）。
GitHub（Check Run・PR コメント・Issue）プロジェクト設定 settings_json.github_locale（ja / en / both）。both は日本語の下に英語を折りたたみで付ける。
MCP呼び出し側が locale 引数で指定。省略時は原文と、あれば翻訳の両方を返す。
エクスポート（CSV・YAML）原文と翻訳の列を両方出す（title, title_en）。

完了条件

  • UI の全画面が日本語・英語で表示でき、メッセージファイルのキーの差分が CI で 0。
  • 上の表の翻訳対象フィールドすべてで、localize() を通して表示言語のテキストが出る。翻訳がない場合は原文と「翻訳中」が出る。
  • UC・TC を編集すると、関連する翻訳が stale になり、再翻訳される。変わっていないステップの翻訳は新しい版に引き継がれる。
  • 英語で実行した実行記録に、表示した翻訳と状態が残る。
  • 「」内の文字列が翻訳で変わらないことをユニットテストで確認している。
