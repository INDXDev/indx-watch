目的

AI の実行を「見て納得できる」ようにし、確定できなかったものだけを人が短時間でレビューする。人の判断をルーブリックと手順の改善につなげる。

注記

  1. 1レビューキュー。runs.verdict = needs_review を優先度 → 古い順に並べる。プロジェクト横断の /review と同じ並び。
  2. 2ジャッジごとの結果と、判定ポリシーが最終判定をどう決めたか。なぜ要確認なのかを 1 行で説明する。
  3. 3エージェントの行動（ツール呼び出し）と観測の組。思考の要約ではなく、実際の操作と画面の変化を見せる。疑わしい行は紫で強調。
  4. 4LLM ジャッジの理由。AC の下位項目ごとに、根拠のスクリーンショットへリンクする。
  5. 5人の確定。理由が空だと確定できない。
  6. 6レビュー結果から TC・ルーブリックの改善案を作る（ai_suggestions.kind = triage）。

表示データ

  • キュー: runs（verdict = needs_review）+ test_cases（priority）
  • 判定の内訳: judgements（judge_kind, verdict, confidence, reason, model, prompt_version）、test_case_versions.decision_policy_json
  • タイムライン: run_steps と evidence（kind = transcript / screenshot / a11y / trace）
  • コスト・所要時間: runs.cost_json、started_at / finished_at
  • 使用データ: runs.fixture_versions_json

操作

  • 合格で確定 / 不合格で確定（理由必須）→ judgements に human を追加し runs.verdict を更新
  • 再実行（同じ TC バージョン・同じデプロイで新しいランを作成）
  • 不合格で確定時に GitHub Issue 作成（S05 と同じフォーム）
  • 改善案の作成 → S04 の AI 提案に表示
  • スクリーンショットの拡大・前後比較、Playwright トレースのダウンロード

AI の役割

  • エージェント（claude-opus-5-5）が自然言語手順を自前ツールで実行し、行動と観測を記録。
  • LLM ジャッジ（claude-sonnet-5-5）が証拠とルーブリックから構造化出力で判定。
  • 人の確定理由を学習材料として、手順・待機時間・ジャッジ種類の改善案を提案。

この画面の完了条件

  • 判定の内訳に「なぜこの最終判定になったか」がポリシーのどの規則によるかとともに表示される。
  • LLM の理由の各項目から、根拠のスクリーンショットへ 1 クリックで移動できる。
  • タイムラインはツール呼び出し単位で表示し、各行にスクリーンショットのサムネイルが付く。
  • 理由なしでは確定ボタンが無効。確定後、キューから消え、次の要確認ランが自動で開く。
  • 確定した人・時刻・理由が judgements と activity_log に残り、後から変更しても履歴が消えない。
  • キュー件数が左ナビの「レビュー待ち」と一致する。
  • guest はこの画面を開けない。
