目的

テスターが「今日なにを、どこで、どの順にテストするか」を考えずに始められるようにする。ログイン後の既定ページ。

注記

  1. 1「次にやること」は 1 件だけ。並び順のルールで先頭の計画アイテムを出す。環境・デプロイ・必要なフィクスチャ・目安時間まで表示する。
  2. 2レビュー待ちは、自分が確認担当の needs_review 実行件数。クリックで S06 のレビューキューへ。
  3. 3並び順: 状態（実行中 → 再実行待ち → 未着手 → ブロック）→ 優先度 → 期限 → 計画内の並び。
  4. 4自分のアサインに出てくる環境だけを出す。入り方は environments.entry_guide_md の要約。パスワードは表示せず、実行画面でコピー可能にする。
  5. 5直近 5 件。行クリックで実行結果（S05 / S06）へ。

表示データ

  • plan_items（assignee_id = 自分、status != done）
  • test_cases / test_case_versions: タイトル・優先度・mode・手順数
  • use_cases: 次にやることカードの UC 名
  • environments / deployments: 環境名・最新デプロイの commit
  • fixture_versions: fixture_refs_json で解決したバージョン
  • runs（executor_id = 自分）: 最近の実行と needs_review 件数
  • releases.target_date: 目標日までの日数

操作

  • 実行を開始: runs を queued → running で作成し、plan_items.status を in_progress に。S05 に遷移
  • 手順を先に見る: S04 を読み取り専用で開く
  • リリースで絞り込み（URL クエリに保持）

AI の役割

  • 目安時間は過去の実行時間の中央値。履歴がなければ AI が手順数と内容から見積もり、AI 推定 を付ける
  • mode が agent のアイテムは人の一覧に出さない（Watch Agent が担当）。hybrid は AI 実行後の確認だけが人のタスクになる

この画面の完了条件

  • 自分にアサインされた未完了アイテムが、注記 3 の順で全件表示される（50 件超はページング）
  • 「次にやること」に一覧の先頭と同じアイテムが出て、[実行を開始] 1 クリックで S05 が開く
  • 期限 2 日以内の期限日は赤字、期限切れは「期限切れ」バッジになる
  • guest は自分にアサインされたプロジェクト・アイテム以外のデータを取得できない（API レベルで検証）
  • アサインが 0 件のとき空状態を出す（下のバリエーション）
  • 初回表示は Server Component で 1 往復、D1 クエリ 3 本以内
