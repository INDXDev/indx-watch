目的

テスターが資料を行き来せずに 1 件のテストケースを最後まで実行し、ステップごとの合否と証拠を残す。中断しても途中から再開できる。

注記

  1. 1実行対象のデプロイメントと URL。access_kind = cf_access の環境では、ランナーが短期トークン付き URL を発行して開く。
  2. 2account 種類のフィクスチャ。パスワードは画面に表示せず、コピー時のみ Secrets から取得する（取得は activity_log に記録）。
  3. 3このステップで使う dataset の該当行。TC バージョンの fixture_refs_json が行を指定する。
  4. 4現在のステップ。やることと期待結果を並べ、平易な文で表示する。
  5. 5クリップボードからの貼り付け・ドラッグで証拠を追加。アップロード先は R2。
  6. 6合否ボタン。キーボードだけで操作できる。
  7. 7不合格時は実際の結果が必須。Issue 作成をオンにすると証拠付きで GitHub Issue を作る。

表示データ

  • ヘッダー: runs（number, state）、test_case_versions（version, steps_json）、test_cases（title, priority）
  • 環境バー: deployments（commit_sha, url）、environments（base_url, access_kind, entry_guide_md）
  • ログイン・データ: fixture_versions（summary_json, secret_ref）。runs.fixture_versions_json に解決済みの版を固定
  • ステップ: run_steps（seq, instruction, expected, verdict, note）
  • 証拠: evidence（kind = upload / screenshot, r2_key）
  • 完了条件: test_case_criteria → acceptance_criteria

操作

  • ステップの合格 / 不合格 / 実行不可 / スキップ（それぞれ judgements に judge_kind = human で記録）
  • 証拠の追加・削除（削除は自分が追加したもののみ）
  • 中断して保存 → マイタスクに「再開」として残る
  • 全ステップ完了で最終判定を確定 → runs.verdict、plan_items.status = done
  • 不合格時に GitHub Issue 作成（issues に保存）

AI の役割

  • 貼り付けたスクリーンショットと期待結果を照合し、「期待結果と違う可能性」を表示する（判定は人が行う）。
  • 不合格時、実際の結果・スクリーンショットから Issue のタイトルと再現手順の下書きを作る。
  • 手順の文が分かりにくいとテスターが報告したら、言い換え案を ai_suggestions に登録する。

この画面の完了条件

  • 開いた時点で URL・ログイン情報・使うデータ行が表示され、1 クリックでコピーまたは環境が開ける。
  • P / F / B / S / J / K と Ctrl+V だけで全ステップを記録できる。
  • 画像の貼り付けから 3 秒以内にサムネイルが表示され、R2 にアップロードされる。
  • 途中でタブを閉じても、記録済みのステップ結果と証拠は失われず、再度開くと次の未実行ステップから始まる。
  • 不合格は「実際の結果」が空だと記録できない。
  • パスワードの値は DOM に含まれない（コピー時に API から取得）。
  • guest は自分にアサインされたランだけ開ける。他人のランの URL は 404。
  • 幅 640px 未満では縦積みレイアウトになり、合否ボタンが画面下部に固定される。

モバイル時のルール

  • 環境バーは折りたたみ、「URL を開く」「ID コピー」「データコピー」の 3 ボタンだけ残す。
  • ステップ一覧は上部の「2 / 5」チップから開くシートにする。
  • 証拠はカメラ・写真ライブラリから追加（ファイル入力）。
  • 合否ボタンは画面下に固定し、safe-area を考慮する。
