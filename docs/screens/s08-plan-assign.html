目的

リリースのテスト範囲と担当を 1 枚で決め、偏りや遅れを早く見つける。人と AI エージェントを同じ一覧で割り振る。

注記

  1. 1計画全体の進捗。各アイテムの最新ランの判定を集計。P0 の合格数は常に別表示。
  2. 2担当者別の負荷。人と Watch Agent を同じ尺度で並べる。
  3. 3AI の割り振り提案。理由を各行に表示し、適用は人が押す。
  4. 4計画アイテムの一覧。状態・担当で絞り込み、行をクリックで TC / 最新ランへ。
  5. 5一括操作。担当・環境・期限・優先度をまとめて変更。

表示データ

  • 計画: test_plans（number, title, status, due_date, release_id）→ releases
  • アイテム: plan_items（test_case_id, environment_id, assignee_id, priority, due_date, status, latest_run_id）
  • 状態バッジ: plan_items.latest_run_id → runs.verdict（ランなしは未実行）
  • 担当: users（kind = human / agent, role）
  • 提案: ai_suggestions（kind = triage、payload に割り振り案）

操作

  • テストを追加（下の「対象の選択」）・アイテム削除（実行済みは削除不可、除外扱い）
  • 担当・環境・期限・優先度の変更（単体 / 一括）。担当変更は相手に通知
  • AI 担当アイテムの一括実行（runner のキューに投入）
  • 提案の適用 / 一部適用 / 却下
  • 計画の複製（次リリース用）、CSV 書き出し

AI の役割

  • TC の mode・過去の自動判定の一致率・手順の安定度から、AI に任せられるものを判定。
  • UC の性質（文言・見た目・業務判断）や作成者からビジネス職への割り振りを提案。
  • 各人の未実行件数と期限から遅延を予測し、付け替えを提案。
  • 計画作成時、PR の変更内容から影響する TC を提案（S11 の影響分析と同じ結果）。

この画面の完了条件

  • 進捗バーの件数が、アイテムの最新ラン判定の集計と一致する（未実行 = ランなし or queued）。
  • 複数行を選び、担当・環境・期限を 1 回の操作で変更でき、activity_log に 1 件ずつ記録される。
  • 担当を変えると、新しい担当のマイタスク（S01）に即時反映される。
  • AI 提案は適用前に対象アイテムと理由が全件見え、適用しても元に戻せる（直前の担当を保存）。
  • guest に割り当てられるのは環境 uat のアイテムのみ。他を選ぶと理由付きで拒否。
  • Watch Agent に割り当てられるのは mode が agent / hybrid / script の TC のみ。
  • 500 件のアイテムでも初期表示 1 秒以内（ページング 100 件単位）。

計画作成時の対象選択

「テストを追加」または新規計画で開くパネル。条件を組み合わせて対象の TC を決め、追加前に件数と内訳を確認します。
