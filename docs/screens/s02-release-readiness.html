目的

リリース判定を「感覚」ではなく条件の充足で決める。何が止めているかを、担当者と証拠つきで即座に辿れるようにする。

注記

  1. 1ゲート条件はプロジェクト設定 projects.settings_json.gate で定義。既定は図の 6 条件。全条件充足で GO。
  2. 2AI 要約は表示データのみを入力に生成し、言及した TC / RUN をリンクにする。データ更新後は「古い要約」表示に変わり、再生成ボタンを出す。
  3. 3判定は「TC ごとの、このリリースの最新デプロイに対する最新の実行」の verdict。古いデプロイの結果は数えない。AC 網羅 = 1 つ以上の ready な TC に紐づく AC 数 / AC 総数。
  4. 4fail・blocked・needs_review を優先度順に表示。fail には Issue の有無を出し、[Issue を作成] が押せる。
  5. 5このリリースに紐づく deployments を新しい順。最新以外の結果は「参考」として灰色表示。

表示データ

  • releases: version・status・target_date
  • test_plans / plan_items（release_id で絞る）
  • runs: plan_item ごとの latest_run_id の verdict
  • features / use_cases / acceptance_criteria / test_case_criteria: 網羅率
  • deployments: release_id・environment・commit_sha・pr_number
  • issues: fail 実行の Issue リンク
  • ai_suggestions（kind=triage）: 要約と再配分案

操作

  • リリース可にする: GO のときだけ有効。releases.status = ready、activity_log に記録
  • NO-GO でも manager は「条件を例外承認して進める」を選べる（理由必須、記録される）
  • 行クリック: 機能 → UC 展開、UC → S03、TC → S04、RUN → S05 / S06
  • レポートを共有: 読み取り専用 URL（Access 保護下）をコピー

AI の役割

  • 止めている要因をまとめ、関連する PR・変更を推定して説明する
  • 未実行の再配分案（担当者の残件と過去実行時間から）を ai_suggestions として出す。適用は manager の承認後
  • AI は判定そのものを変えない

この画面の完了条件

  • ゲート 6 条件の値が、同じデータを SQL で集計した値と一致する（テストで検証）
  • 分布バーの合計がその行の TC 数と一致し、合計行が PLAN の件数と一致する
  • 最新デプロイが変わると、それ以前の実行は判定集計から外れる
  • GO 以外で [リリース可にする] は押せない（例外承認を除く）。例外承認は理由なしで保存できない
  • AI 要約の各 TC / RUN 参照がリンクとして機能する。要約生成に失敗しても画面の他部分は表示される
  • guest はこの画面にアクセスできない（403）
