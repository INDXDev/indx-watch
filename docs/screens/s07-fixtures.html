目的

テストデータをスプレッドシートや個人の手元から 1 か所に集め、誰が・いつ・何を変えたか、どの実行がどの版を使ったかを追えるようにする。

注記

  1. 1種類ラベル（dataset / seed / file / account）、最新版、使用 TC 数、最終更新者。
  2. 2CSV・JSON の dataset はセル単位で編集。保存で新しい版を作る（既存の版は変更しない）。
  3. 3行単位の差分。追加=緑、変更=黄（変更前 → 変更後）、削除=赤の取り消し線。キー列は summary_json.key_column（既定は 1 列目）。
  4. 4履歴。「この版に戻す」は過去の版の内容で新しい版を作る（履歴は消さない）。
  5. 5ファイルアップロード。R2 に保存し、sha256 が同じなら新しい版を作らない。
  6. 6AI 提案。TC の手順と既存データを照らして不足を指摘。採用しても下書きになり、保存は人が行う。

表示データ

  • 一覧: fixtures（number, name, kind, environment_id, current_version_id）
  • データ・差分: fixture_versions（version, r2_key, content_type, size, sha256, summary_json, change_note, created_by）。本体は R2 fixtures/SHOP/{fixture_id}/v{n}/
  • 使用 TC: test_case_versions.fixture_refs_json を逆引き
  • 使った実行: runs.fixture_versions_json
  • AI 提案: ai_suggestions（kind = fixture）

値は Workers Secrets / Secrets Store にのみ保存。D1 には secret_ref（参照名）だけ。値の変更は manager 以上、変更しても値は履歴に残さず「変更した事実」だけ残す。

AI の役割

  • TC の手順・期待結果から、必要なデータ行の不足・期限切れ（例: expires_at が過去になった有効クーポン）を検出。
  • PRD や PR の差分から新しいフィクスチャの初版を提案。
  • アップロードされた CSV の列の意味を推定し summary_json に説明を書く。

この画面の完了条件

  • CSV / JSON をブラウザでセル編集し、変更メモ付きで新しい版として保存できる。変更メモは必須。
  • 任意の 2 版を選んで行単位の差分を表示できる。
  • 「この版に戻す」で新しい版が作られ、元の版も履歴に残る。
  • 各版から、その版を使った実行の一覧へ移動できる。
  • 使用中の TC が latest を参照している場合、保存前に「影響する TC: 3 件」を表示する。
  • account の値は画面・API レスポンス・D1 のどこにも平文で現れない。
  • 20MB を超えるファイルはアップロード前に理由付きで拒否される。
  • guest はこの画面を開けない。tester は閲覧と dataset / file の編集、account の編集は manager 以上。
