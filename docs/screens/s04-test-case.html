目的

人と AI エージェントが同じ手順を読んで同じ結果を出せるテストケースを、履歴つきで管理する。判定の方法（何で pass とするか）も TC と一緒に決める。

注記

  1. 1表示しているのは test_cases.current_version_id のバージョン。実行は開始時点のバージョン ID を runs.test_case_version_id に保存するので、後で TC を直しても過去の実行の意味は変わらない。
  2. 2steps_json は [{seq, instruction, expected, evidence: ["screenshot","dom"], judges: ["assert"], fixture_ref?, guest_text?}]。{base_url} などの変数は実行時に環境から展開。
  3. 3AI アシストは表示時に非同期で取得し、TC バージョン単位でキャッシュ。「反映」は編集モードの下書きに入るだけで、保存は人が行う。
  4. 4フィクスチャはバージョン固定（v2 固定）か latest を選べる。P0 は固定を推奨し、latest のときは警告を出す。
  5. 5判定設定は judges_json と decision_policy_json。詳細と既定ポリシーは AI ネイティブ設計。

表示データ

  • test_cases（number・title・priority・mode・status・owner_id・origin）
  • test_case_versions（preconditions_md・steps_json・judges_json・decision_policy_json・fixture_refs_json・script・change_note）
  • test_case_criteria → acceptance_criteria → use_cases → features
  • fixtures / fixture_versions
  • runs（test_case_id で最近 9 件）
  • ai_suggestions（kind=tc_generate、この TC を source に持つもの）

操作

  • 編集 → 保存で test_case_versions に新しい行（version +1、change_note 必須）を追加し、current_version_id を更新
  • この TC を実行 ▾: 環境・デプロイを選び、自分で実行（S05）/ エージェントで実行（S06）
  • 履歴タブ: 任意の 2 バージョンの差分（手順・期待結果・判定設定・フィクスチャ参照）
  • 状態変更: draft → ready（manager）、ready → deprecated（理由必須）

AI の役割

  • 手順のあいまいさ・直書きデータ・1 ステップに複数動作がある箇所を指摘
  • 期待結果から assert の候補（URL・テキスト・要素）と LLM ルーブリックを提案
  • mode を manual から agent / hybrid に変えられるかを、手順の内容から判定して提案

この画面の完了条件

  • 保存のたびに新しいバージョンができ、既存バージョンの行は更新されない（D1 上で UPDATE が発生しないことをテスト）
  • change_note が空のときは保存できない
  • 任意の 2 バージョンの差分が手順単位で表示される
  • 手順は 1〜50 件。並べ替えで seq が振り直される
  • draft の TC は「この TC を実行」で agent 実行のみ可能（試し実行）。計画には入れられない
  • フィクスチャが latest 参照の P0 TC には警告が出る
  • AI アシストが失敗・タイムアウトしても画面は表示され、「AI の指摘を取得できませんでした」と出る

状態のバリエーション

編集モード

手順は行単位で編集し、ドラッグで並べ替えます。変数（{base_url}、{FX-9.visa_ok.number}）は入力補完で挿入できます。保存時に変更メモの入力を求めます。
