目的

テスターが社内・社外・海外にいても、「誰が・いつ・どこから・どうやって入り、何をしたか」を後から正確に追えるようにする。不審なログインの早期発見と、実行結果の証跡（誰がどの環境でどう判定したか）を兼ねる。

注記

  1. 1サマリは今日（JST）の値。失敗・拒否は直近 24 時間の access_events.allowed = 0。「新しい端末・場所」は、そのユーザーの過去 90 日の login_sessions にない国、または ua_json の組み合わせ。
  2. 2AI 要約は異常の候補と根拠（対象レコードへのリンク）だけを示す。不正と断定しない。入力は集計済みデータのみで、IP は渡さない。
  3. 3フィルタはユーザー・期間・国・IdP・操作種別・プロジェクト。URL のクエリに保持し、共有できる。CSV 書き出しはフィルタ結果と同じ範囲で、書き出し自体を activity_log に記録。
  4. 4ログイン時刻は JST と本人のタイムゾーン（users.timezone）を併記。IP は admin のみ表示。「失効させる」は Cloudflare Access の revoke_user API を呼び、login_sessions.end_reason = revoked、revoked_by を記録。
  5. 5Access で拒否されたログインは Worker に届かないため、Logpush（access_requests → R2）と REST API の取り込みで表示する。未登録メールは user_id = null のまま表示。
  6. 6操作時間は runs.active_ms（画面が前面にあり操作している時間の合計）。待ち時間や放置は含まない。
  7. 7タイムラインは work_sessions を帯で、その中の page_views と activity_log を時刻順に表示。各行に Ray ID と場所（request.cf の city / colo）を付け、Cloudflare 側のログと突き合わせられる。秘密値のコピーは「操作した事実」だけを記録し、値は記録しない。
  8. 8記録内容の告知と同意状況（users.privacy_ack_at）、保持期間を常に画面下部に表示する。

表示データ

  • サマリ・ログイン一覧: login_sessions（idp_type, geo_json, ip_last, ua_json, is_warp, access_iat, ended_at, end_reason）＋ users（name, role, timezone, locale）
  • 拒否・失敗: access_events（occurred_at, email, allowed, connection, country, ip）
  • タイムライン: work_sessions、page_views（screen_id, visible_ms, ray_id）、activity_log（action, target, ray_id, city, colo）
  • 操作時間: runs.active_ms、run_steps.active_ms
  • 取り込み状況: ingest_cursors（access_rest / access_graphql / access_users）

操作

  • セッションを失効させる（admin のみ。理由の入力必須）
  • ユーザーを選んでタイムラインを開く
  • フィルタ・CSV 書き出し
  • Access ログを今すぐ取り込む（取り込みが遅れているとき）

AI の役割

初めての国・端末、深夜帯の大量操作、拒否の連続などの「確認したほうがよい点」を短く要約し、根拠のレコードにリンクする。判定や自動失効はしない（失効は人が行う）。

この画面の完了条件

  • admin 以外が /admin/activity を開くと 403 になる（manager は下記の作業サマリ画面へリダイレクト）。
  • Access でログインすると、1 分以内に login_sessions の行がこの一覧に出る（IdP・国・都市・ASN・colo・端末・WARP が埋まる）。
  • Access で拒否されたログインが、取り込み間隔（既定 15 分）以内に「拒否・失敗」に出る。
  • 「失効させる」を押すと Access のセッションが失効し、そのユーザーの次のリクエストが再ログインになる。行の状態が「失効」になり、誰が失効させたかが残る。
  • タイムラインの各イベントに Ray ID・時刻・場所があり、RUN の行から S06 / S05 の実行記録へ移動できる。
  • 時刻が JST とユーザーのタイムゾーンで正しく表示される（UTC 保存）。
  • この画面の閲覧と CSV 書き出しが activity_log に記録される。
  • 最終取り込みから 60 分以上経つと警告が出る。
