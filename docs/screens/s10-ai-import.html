目的

文書に書かれた要件を、手で写さずに仕様ツリー（機能 → UC → AC → TC）とフィクスチャに変換する。重複と情報不足を AI に見つけさせ、人は「採用するか」だけを判断する。

注記

  1. 1入力は 3 種類。ファイルは R2 の imports/SHOP/{suggestion_id}/ に保存し、PR は GitHub App 経由で説明文と差分を取得。対象機能とリリースを指定すると提案の範囲が絞られる。
  2. 2提案は ai_suggestions（kind=spec_import）1 行。モデル名・プロンプトバージョン・所要時間・実行者を必ず表示。
  3. 3選択中の項目が根拠にした原文をハイライト。根拠のない提案は出さない（プロンプトで出典引用を必須にしている）。
  4. 4既存の UC・TC との類似度を表示し、統合 / 更新 / 別に作る を選べる。更新を選ぶと既存 TC に新バージョンの下書きを作る。信頼度 0.5 未満は既定で未選択。
  5. 5一括作成でも origin = 'ai'・status = 'draft'。ready への変更は S03 / S04 で人が行う。

表示データ

  • ai_suggestions: kind, source_json（入力の種類・R2 キー・PR 番号）, payload_json（提案ツリー・類似度・信頼度・出典範囲）, status, model, prompt_version
  • 既存の features / use_cases / acceptance_criteria / test_cases（重複検出の比較対象）
  • fixtures（既存フィクスチャへのバージョン追加の判定）

操作

  • 入力の種類を選び、AI で案を作る（manager / tester）
  • 項目ごとに 採用 / 編集 / 却下、重複は 統合 / 更新 / 別に作る
  • 選択した項目を下書きで一括作成
  • 情報不足の質問を担当者に送る（コメントとして記録）
  • 過去の取り込み履歴を開き、結果（採用 / 却下数）を見る

AI の役割

  • claude-opus-5-5 で文書を構造化し、仕様ツリーとフィクスチャ案を構造化出力で返す。
  • 既存仕様との類似度判定（埋め込みではなく、候補を絞ってから LLM で比較）。
  • TBD・矛盾・曖昧な箇所を「質問」として出し、勝手に補完しない。
  • 優先度（P0〜P3）と実行モード（manual / agent など）を推定するが、確定は人。

この画面の完了条件

  • テキスト・PDF / Markdown / CSV・PR 番号の 3 種類から提案を作れる。
  • 提案の生成中は進捗が表示され、画面を離れても ai_suggestions に結果が残り、後から開ける。
  • すべての提案項目に出典範囲があり、選択すると原文がハイライトされる。
  • 既存項目と類似度 70% 以上なら重複候補として表示され、統合 / 更新 / 別に作る を選べる。
  • 一括作成で作られた UC・AC・TC・フィクスチャはすべて origin = 'ai'、TC は status = 'draft' で、activity_log に提案 ID とともに記録される。
  • 却下した項目と理由は payload_json に残り、次回の取り込みで同じ提案を繰り返さない。
  • guest はこの画面にアクセスできない（404 ではなく権限エラーを表示）。
