目的

テスト環境への入り方を属人化させない。テスターが「URL はどれ？」「ログインは？」「データが壊れたら？」を誰にも聞かずに解決できるようにする。

注記

  1. 1環境一覧。ヘルスチェックは runner の Cron が 5 分ごとに GET base_url を実行した最新結果。現在のデプロイは deployments の最新 1 件。
  2. 2entry_guide_md を Markdown でレンダリング。マイタスク（S01）と手動ランナー（S05）の「環境に入る」からも同じ内容を表示する。
  3. 3kind=account のフィクスチャのうち、この環境に紐づくもの。パスワードは表示せず、コピー時だけサーバーから取得（監査ログに記録）。
  4. 4秘密情報は参照名のみ。値の登録は wrangler secret put またはダッシュボードで行う。
  5. 5接続テストは Browser Rendering で実際にページを開き、テストアカウントでのログインまで確認する。
  6. 6reset_hook_json の設定。テスト対象アプリ側に用意してもらうエンドポイント。実行前処理で自動的にも呼ばれる。
  7. 7preview はテンプレート環境。PR ごとのデプロイメントとして扱い、環境自体は 1 行。

表示データ

  • environments: name, kind, base_url, access_kind, access_secret_ref, entry_guide_md, reset_hook_json, is_default
  • deployments: environment_id ごとの最新 commit_sha, pr_number, release_id
  • fixtures / fixture_versions: kind=account, environment_id = この環境
  • ヘルスチェック結果: activity_log（action = env.health）の最新
  • リセット結果: activity_log（action = env.reset）

操作

  • 環境を追加・編集（manager / admin）
  • 入り方ガイドを編集（manager / tester。変更は履歴に残る）
  • 環境を開く・ガイド URL をコピー（全員）
  • パスワードをコピー（tester 以上。admin アカウントは manager 以上）
  • 接続テスト・データをリセット（tester 以上）

AI の役割

  • 接続テスト失敗時に、ログとスクリーンショットから原因候補を要約（例: 「Access のトークン期限切れの可能性」）。
  • リポジトリの README・docker-compose から入り方ガイドの下書きを提案（AI 提案 として表示、採用は人）。

この画面の完了条件

  • 環境一覧に名前・URL・入り方・最新ヘルスチェック（ステータスコード・応答時間・経過時間）・現在の commit が表示される。
  • 入り方ガイドの Markdown が表示され、編集すると activity_log に差分が残る。
  • パスワード・トークンの値がページの HTML・API レスポンスに一度も含まれない（コピー操作時の専用エンドポイントのみ返す）。
  • guest は自分にアサインされた環境（例: uat）だけが見え、アクセス方式とリセット設定は表示されない。
  • 「接続テスト」を押すと 60 秒以内に各チェックの成否が表示される。
  • 「データをリセット」はリセットフックを呼び、成功 / 失敗と所要時間を表示する。実行中は二重実行できない。
  • preview の PR デプロイが GitHub から届くと、手動操作なしで一覧に反映される。
