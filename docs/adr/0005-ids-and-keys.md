# 0005. ULID machine IDs; human keys assigned locally and renumbered on conflict

- Status: accepted
- Date: 2026-11-19

## Context

Files are created offline, on branches, by people and agents. People need short keys (`TC-128`) for conversation and Playwright tags. A central counter would require a server.

## Decision

- Machine IDs are `{prefix}_{ULID}`, generated by whoever creates the file. Results reference machine IDs.
- `iw new` assigns the next free key by scanning the bundle (and the keys seen in the local result replica, so retired keys are not reused).
- When two branches create the same key, `iw check` reports it and `iw check --fix` renumbers the item whose ID sorts later, updating references inside the bundle. It prints the old → new mapping so Playwright tags can be updated (the reporter also accepts the machine ID as a tag).

## Consequences

- No server is needed to create anything.
- A renumbered test case keeps its results (same machine ID); only display keys change.

## Alternatives considered

- **Server-assigned keys on first sync** — requires a server for git-only teams; keys would be missing in PRs.
- **Keys only, no IDs** — renames and conflicts would break result links.
